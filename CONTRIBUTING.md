# Contributing

wgm's rules may change until 1.0, and reports from people who use it show where it is wrong. The way to send one is an issue on https://github.com/mirandadam/wgm.

## Reporting a problem

An issue is most useful when it holds:

- the file and the passage, quoted as it reads, and the tag or commit of wgm you read it in;
- what following it did, or would do, in your work, and what you expected instead;
- for a recipe you ran, which recipe, what your `WGM.md` said where it mattered, and what the person or assistant running it did.

State each without your repository's names, code or data, because the issue is public.

A rule that would do harm if followed to the letter, two files that contradict each other, and a claim that is false are the reports that matter most. A sentence that is only unclear is worth reporting too.

## Proposing a change

Write the wording you propose in the issue, beside the passage it would replace. Each release reaches this repository as a single commit from the private repository where wgm is written, so a pull request is not merged as it stands. One that shows a proposed wording is read like an issue.
